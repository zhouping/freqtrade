## 1. 环境准备与项目初始化
```bash
# 进入项目根目录并激活虚拟环境
cd /home/kali/Project/freqtrade
source .venv/bin/activate

# 检查 CLI 可用性
freqtrade --version
```
> 若未创建虚拟环境，请参考 `文档/本地开发调试指南.md` 第 1 节完成 `python -m venv .venv && pip install -e .` 等步骤。

### 创建用户目录 & 配置文件
```bash
# 第一次使用时生成 user_data 结构（只需执行一次）
freqtrade create-userdir --userdir user_data
```
`user_data/` 目录结构如下：
```
user_data/
├─ data/                # 存放历史 K 线 CSV
├─ strategies/          # 放置自定义策略 Python 文件
├─ logs/                # 运行日志
├─ backtest_results/    # 回测产出（HTML、CSV、JSON）
└─ config.json          # 主配置信息
```
复制官方示例配置并打开 dry‑run（防止真实下单）：
```bash
cp config_examples/config_binance.example.json user_data/config.json
sed -i 's/"dry_run": false/"dry_run": true/' user_data/config.json
```
如需实盘请自行将 `dry_run` 改为 `false`，但在调试阶段强烈建议保持 `true`。

## 2. 编写策略文件的基本规范
1. **文件位置**：`user_data/strategies/YourStrategy.py`
2. **类名**：必须继承 `IStrategy`（或 `Strategy` 基类），类名即策略名称。
3. **必须实现的方法**：
   - `populate_indicators(self, dataframe, metadata=None)`: 计算技术指标并返回 DataFrame。 
   - `populate_entry_trend(self, dataframe, metadata=None)`: 根据指标返回买入信号（`dataframe['enter_long'] = 1` 等）。
   - `populate_exit_trend(self, dataframe, metadata=None)`: 返回卖出信号。
4. **可选属性**（推荐在文件顶部定义）：
   - `timeframe = '1h'`
   - `minimal_roi = {"0": 0.02}`
   - `stoploss = -0.10`
   - `use_custom_stoploss = False`
5. **示例框架**：
   ```python
   from freqtrade.strategy import IStrategy
   import talib.abstract as ta

   class MyStrategy(IStrategy):
       timeframe = '1h'
       minimal_roi = {"0": 0.02}
       stoploss = -0.10

       def populate_indicators(self, dataframe, metadata=None):
           dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)
           return dataframe

       def populate_entry_trend(self, dataframe, metadata=None):
           dataframe['enter_long'] = (dataframe['rsi'] < 30).astype('int')
           return dataframe

       def populate_exit_trend(self, dataframe, metadata=None):
           dataframe['exit_long'] = (dataframe['rsi'] > 70).astype('int')
           return dataframe
   ```

## 3. 本地调试技巧
### 3.1 使用 dry‑run 与日志
```bash
freqtrade trade -c user_data/config.json \
    --strategy MyStrategy \
    --dry-run-wallet 1000 \
    --loglevel DEBUG
```
- `--dry-run-wallet` 为回测提供初始资金。
- `DEBUG` 日志会将每根 K 线、指标、信号以及交易细节记录在 `user_data/logs/freqtrade.log`，便于追踪。

### 3.2 交互式调试（pdb）
在策略代码中加入 `import pdb; pdb.set_trace()`，然后运行上面的 `trade` 命令，程序会在触发该行时暂停，您可以检查 `dataframe` 内容。

### 3.3 单元测试（推荐）
Freqtrade 自带 pytest 框架，可在 `tests/` 目录编写策略单元测试。
```python
# tests/test_mystrategy.py
import pandas as pd
from freqtrade.strategy import IStrategy
from user_data.strategies.mystrategy import MyStrategy

def test_populate_indicators():
    df = pd.DataFrame({"open": [100,101], "close": [102,103]})
    df = MyStrategy().populate_indicators(df)
    assert "rsi" in df.columns
```
执行：`pytest -q`，确保所有测试通过后再进入回测。

## 4. 生成或准备虚拟 K 线数据
### 4.1 使用官方 `download-data`
```bash
freqtrade download-data \
    -c user_data/config.json \
    --exchange binance \
    --base BTC \
    --quote USDT \
    --timeframe 1h \
    --timerange 20220101-20230101
```
下载的 CSV 位于 `user_data/data/binance/BTC_USDT/1h/data_1h.csv`。文件格式：`timestamp,open,high,low,close,volume`（UTC）。

### 4.2 手动生成虚拟 K 线（无需联网）
如果网络受限，可自行生成随机 CSV，示例脚本已在 `本地开发调试指南.md` 第 2.2 节提供。关键点：
- 每行时间戳递增 `3600` 秒（1h）。
- `open、high、low、close` 必须保持 `low <= open/close <= high`。
- 保存至同样的目录结构即可被策略读取。

## 5. 回测前的准备工作
1. **确保数据已就绪**：`user_data/data/<exchange>/<pair>/<tf>/data_*.csv` 文件存在且完整。
2. **确认策略文件已放置**：`user_data/strategies/MyStrategy.py` 并且类名与 `--strategy` 参数一致。
3. **检查配置**：`config.json` 中 `exchange`、`pairlist` 与下载时使用的保持一致；`dry_run` **可不改**，回测不依赖 API 密钥。
4. **可选：自定义回测参数**（如 `--timerange`、`--timeframe`）根据需求调整。

## 6. 执行回测并导出报告
```bash
freqtrade backtesting \
    -c user_data/config.json \
    --strategy MyStrategy \
    --timerange 20220101-20230101 \
    --timeframe 1h \
    --loglevel DEBUG \
    --export trades,plot,summary
```
- `trades` → `user_data/backtest_results/trades.csv`
- `plot`  → `user_data/backtest_results/backtest_results.html`
- `summary` → `user_data/backtest_results/summary.json`

**导出文件说明**：
- `backtest_results.html` 包含累计净值曲线、每日收益分布、最大回撤可视化。 
- `summary.json` 提供关键指标：`total_profit`, `profit_abs`, `max_drawdown`, `sharpe_ratio`, `sortino_ratio`, `trade_count`, `win_rate` 等。
- `trades.csv` 记录每笔交易的完整信息（时间、价格、手续费、盈亏等），方便在 Excel/PowerBI 进一步分析。

## 7. 回测结果分析与常用指标
| 指标 | 含义 | 判断依据 |
|------|------|----------|
| **累计净值** | 资金随时间的增长曲线 | 上升趋势 → 正向收益，波动大则风险高 |
| **最大回撤 (Max Drawdown)** | 资金从最高点到最低点的跌幅 | 通常希望 < 20%；高于 30% 需要审视风险控制 |
| **夏普比率 (Sharpe Ratio)** | 超额收益与波动率之比 | > 1 为可接受，> 2 为优秀 |
| **胜率 (Win Rate)** | 盈利交易占比 | 高胜率不一定好，需要结合盈亏幅度 |
| **平均盈亏 (Avg Profit / Avg Loss)** | 单笔盈亏的均值 | 正比例大于 1 表示盈亏比好 |
| **交易次数 (Trade Count)** | 策略执行的交易总次数 | 反映策略活跃度 |
| **收益回撤比 (Profit/Drawdown)** | 总收益与最大回撤的比值 | > 2.0 为较好策略，> 3.0 为优秀策略 |

通过 `summary.json` 可直接获取上述数值；若想自定义更细粒度分析，可读取 `trades.csv` 用 pandas 计算。

### 7.1 关键回测指标详细说明

#### 累计净值 (Total Profit)
累计净值表示策略在整个回测期间的总收益率。例如，累计净值为 0.127 表示初始资金增长了 12.7%。

#### 夏普比率 (Sharpe Ratio)
夏普比率衡量的是每单位总风险所产生的超额回报。夏普比率 > 1 被认为是可接受的，> 2 是优秀的表现。

#### 胜率 (Win Rate)
胜率是指在所有交易中盈利交易的百分比。例如，胜率 0.62 表示 62% 的交易是盈利的。

#### 最大回撤 (Max Drawdown)
最大回撤是指在特定时期内从峰值到谷底的最大损失百分比。通常希望 < 20%；高于 30% 需要审视风险控制。

#### 平均盈亏比 (Avg Profit / Avg Loss)
平均盈亏比是平均盈利与平均亏损的比值。正比例大于 1 表示盈亏比好，策略具有良好的风险回报特征。

#### 交易次数 (Trade Count)
交易次数反映了策略的活跃度。交易次数过多可能导致过度交易和高手续费，过少可能意味着策略不够活跃。

#### 收益回撤比 (Profit/Drawdown)
收益回撤比是总收益与最大回撤的比值。该比率 > 2.0 被认为是较好的策略，> 3.0 是优秀策略。

通过 `summary.json` 可直接获取上述数值；若想自定义更细粒度分析，可读取 `trades.csv` 用 pandas 计算。

## 8. 常见问题与排查指南
| 现象 | 可能原因 | 解决办法 |
|------|----------|----------|
| `No data found for pair …` | 数据目录或文件名错误 | 检查 `user_data/data/<exchange>/<pair>/<tf>/data_*.csv` 是否存在；确认 `config.json` 中 `pairlist` 与下载保持一致。 |
| `Failed to parse timerange` | `--timerange` 格式不符 | 必须使用 `YYYYMMDD-YYYYMMDD`，且左闭右开。 |
| 回测运行异常慢（>5 分钟） | 数据量大且未开启缓存 | 使用更粗的 `timeframe`（如 `4h`）或在 `config.json` 中启用 `sqlite` WAL 模式；亦可尝试 `--processes N`（实验性并行） |
| 策略报错 `AttributeError: 'DataFrame' object has no attribute …` | 在 `populate_entry_trend` 中使用了未在 `populate_indicators` 中创建的列 | 在 `populate_indicators` 首先生成该列，或在 `entry_trend` 前加入 `dataframe['col'] = np.nan` 进行占位。 |
| `backtest_results.html` 未生成 | 未使用 `--export plot` 或输出目录被误改 | 添加 `--export plot`，或检查 `user_data/backtest_results/` 是否有写权限。 |

### 查看日志
```bash
tail -n 50 user_data/logs/freqtrade.log
```
日志会记录每根 K 线的加载、指标计算、信号产生以及每笔交易的细节，是定位错误的第一手资料。

## 9. 完整示例脚本（一步到位）
以下 Bash 脚本把 **环境准备 → 数据下载 → 回测** 全流程自动化，可直接复制运行（请自行替换 `MyStrategy` 为实际策略文件名）：
```bash
#!/usr/bin/env bash
set -e

PROJECT_ROOT="/home/kali/Project/freqtrade"
cd "$PROJECT_ROOT"
source .venv/bin/activate

# 1. 初始化用户目录（若已存在则跳过）
freqtrade create-userdir --userdir user_data || true

# 2. 复制示例配置并启用 dry‑run
cp -n config_examples/config_binance.example.json user_data/config.json || true
sed -i 's/"dry_run": false/"dry_run": true/' user_data/config.json

# 3. 下载 1 年 BTC/USDT 1h K 线（如已有可省略）
freqtrade download-data \
    -c user_data/config.json \
    --exchange binance \
    --base BTC \
    --quote USDT \
    --timeframe 1h \
    --timerange 20220101-20230101

# 4. 回测自定义策略（请把 MyStrategy.py 放到 user_data/strategies/）
freqtrade backtesting \
    -c user_data/config.json \
    --strategy MyStrategy \
    --timerange 20220101-20230101 \
    --timeframe 1h \
    --loglevel DEBUG \
    --export trades,plot,summary

# 5. 打开可视化报告（可选）
xdg-open user_data/backtest_results/backtest_results.html
```
运行结束后，`user_data/backtest_results/` 中即拥有完整的回测报告与交易明细。
