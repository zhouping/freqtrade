## 2. 了解 IStrategy 基类

所有自定义策略必须继承 `freqtrade.strategy.IStrategy`（位于 `freqtrade/strategy/interface.py`），该基类定义了以下关键属性与方法：

| 属性/方法 | 说明 |
|---|---|
| `timeframe` | 使用的时间周期，例如 `'5m'`、`'1h'`。 |
| `stoploss` | 固定止损比例，负数表示亏损阈值，例如 `-0.10`（10%） |
| `minimal_roi` | ROI 字典，用于在回测/实时中自动平仓，例如 `{"0": 0.02}` 表示任何盈利 2% 即平仓 |
| `populate_indicators(self, dataframe, metadata)` | 在 DataFrame 中添加指标列，返回完整的 dataframe |
| `populate_entry_trend(self, dataframe, metadata)` | 根据指标生成 `enter_long`/`enter_short` 信号列 |
| `populate_exit_trend(self, dataframe, metadata)` | 根据指标生成 `exit_long`/`exit_short` 信号列 |
| 其它回调（可选）| `custom_trade_info`, `confirm_trade_entry`, `confirm_trade_exit`, `adjust_trade_position` 等 |

> **注意**：在 `populate_*` 方法中必须 **返回 dataframe**，并且 **不要修改 `open`、`high`、`low`、`close`、`volume`** 列的结构。

## 3. 创建新策略

### 3.1 使用 CLI 生成模板

```bash
freqtrade new-strategy --strategy MyStrategy          # 基础模板
freqtrade new-strategy --strategy MyStrategy --template minimal   # 空白模板
freqtrade new-strategy --strategy MyStrategy --template advanced  # 包含示例指标的完整模板
```

生成的文件默认位于 `user_data/strategies/`，文件名为 `MyStrategy.py`。随后可复制到项目的 `freqtrade/strategy/` 目录或直接使用路径参数 `--strategy-path`。

### 3.2 手动复制示例

如果想基于官方示例 `sample_strategy.py` 自行修改，可直接复制：

```bash
cp freqtrade/templates/sample_strategy.py freqtrade/strategy/MyStrategy.py
```

## 4. 编写策略文件

下面给出一个最小可运行的示例（基于 `strategy-101.md` 中的代码）：

```python
from freqtrade.strategy import IStrategy
from pandas import DataFrame
import talib.abstract as ta

class MyStrategy(IStrategy):
    """自定义策略示例"""

    timeframe = '15m'
    # 1. 止损设置（-10%）
    stoploss = -0.10
    # 2. ROI 设置（盈亏 1% 即平仓）
    minimal_roi = {"0": 0.01}
    # 3. （可选）策略启动所需的历史蜡烛数
    startup_candle_count = 50

    def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        """在 dataframe 中添加技术指标列"""
        # 示例：RSI
        dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)
        # 示例：20 期 EMA
        dataframe['ema20'] = ta.EMA(dataframe, timeperiod=20)
        return dataframe

    def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        """生成买入信号（enter_long=1）"""
        dataframe.loc[
            (dataframe['rsi'] < 30) & (dataframe['close'] > dataframe['ema20']),
            'enter_long'] = 1
        return dataframe

    def populate_exit_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        """生成卖出信号（exit_long=1）"""
        dataframe.loc[
            (dataframe['rsi'] > 70) | (dataframe['close'] < dataframe['ema20']),
            'exit_long'] = 1
        return dataframe
```

**关键点**：
- 使用 `dataframe.loc[condition, 'column'] = 1` 而不是 `if dataframe['col'] > x:`，避免 pandas 的向量化错误。
- 所有指标列必须在 `populate_indicators` 中创建，后续函数直接引用即可。

## 5. 常用技术指标

Freqtrade 默认集成三大技术指标库：
- **ta-lib**（`import talib.abstract as ta`）
- **pandas‑ta**（`import pandas_ta as pta`）
- **technical**（`from technical import indicator`）

下面列出常用指标及其常见参数：

| 指标 | 典型参数 | 示例代码 |
|---|---|---|
| RSI | `timeperiod=14` | `dataframe['rsi'] = ta.RSI(dataframe, timeperiod=14)` |
| EMA | `timeperiod=n` | `dataframe['ema20'] = ta.EMA(dataframe, timeperiod=20)` |
| SMA | `timeperiod=n` | `dataframe['sma50'] = ta.SMA(dataframe, timeperiod=50)` |
| MACD | `fastperiod=12, slowperiod=26, signalperiod=9` | `macd = ta.MACD(dataframe); dataframe['macd'] = macd['macd']` |
| Bollinger Bands | `nbdevup=2, nbdevdn=2, timeperiod=20` | `bb = ta.BBANDS(dataframe); dataframe['bb_lower'] = bb['lowerband']` |
| ADX | `timeperiod=14` | `dataframe['adx'] = ta.ADX(dataframe)` |

> **性能提示**：仅保留实际使用的指标，避免在 `populate_indicators` 中一次性加载全部指标，会显著增加 CPU 与内存开销。

## 6. 入场与出场信号

### 6.1 信号列约定
- **enter_long** / **enter_short**：值为 `1` 表示产生对应方向的买入信号。
- **exit_long** / **exit_short**：值为 `1` 表示产生对应方向的卖出信号。
- 信号列必须始终存在，即使策略只做多，仍需返回 `enter_long` / `exit_long` 列。

### 6.2 常见写法
```python
# 多头入场：RSI 超卖且收盘价在 EMA 上方
condition = (dataframe['rsi'] < 30) & (dataframe['close'] > dataframe['ema20'])
dataframe.loc[condition, 'enter_long'] = 1
```

### 6.3 防止冲突（碰撞信号）
若同一根蜡烛上同时出现 `enter_*` 与 `exit_*`，Freqtrade 会视为 **冲突信号**，默认不下单。可通过以下两种方式处理：
1. 在 `populate_entry_trend` 中提前剔除已经满足退出条件的行。
2. 实现 `confirm_trade_entry` 回调，在回调里自行决定是否接受该信号。

## 7. 止损、ROI 与仓位管理

| 参数 | 说明 |
|---|---|
| `stoploss` | 固定止损比例（负值），如 `-0.10` 表示亏损 10% 时强制平仓。 |
| `minimal_roi` | ROI 字典，键为运行时间（秒），值为目标收益率。例如 `{"0": 0.01, "3600": 0.03}` 表示立即平仓 1%，持仓 1 小时后若收益 >=3% 再平。 |
| `trailing_stop`（可选） | 启用追踪止损，配合 `trailing_stop_positive`、`trailing_stop_positive_offset` 使用。 |
| `max_open_trades`（配置文件） | 同时最多可持有的交易数量。 |
| `startup_candle_count` | 策略启动所需的历史蜡烛数，确保所有指标都有有效值。 |

> **最佳实践**：在回测前先使用 `freqtrade lookahead-analysis` 与 `freqtrade recursive-analysis` 检查 `startup_candle_count` 与指标前瞻性问题。

## 8. 策略回调函数（高级特性）

Freqtrade 允许在关键时刻插入自定义回调，以实现更细粒度的控制。

| 回调函数 | 触发时机 | 常用场景 |
|---|---|---|
| `custom_trade_info(self, pair, order, trade)` | 交易创建后 | 添加自定义标签、记录额外信息 |
| `confirm_trade_entry(self, pair, order, trade, **kwargs)` | 生成入场信号前 | 根据外部因素（如风控、行情）决定是否执行入场 |
| `confirm_trade_exit(self, pair, order, trade, **kwargs)` | 生成出场信号前 | 防止在高波动时误平仓 |
| `adjust_trade_position(self, trade, **kwargs)` | 持仓期间 | 动态修改止损、移动止盈或加仓 |

### 示例：限制每对最大持仓时间
```python
from datetime import timedelta

class MyStrategy(IStrategy):
    max_trade_duration = timedelta(hours=6)  # 6 小时后强制平仓

    def confirm_trade_exit(self, pair, order, trade, **kwargs):
        if trade.close_date - trade.open_date > self.max_trade_duration:
            return True  # 触发平仓
        return False
```

## 9. 调试、回测与前向测试

### 9.1 本地调试
- 使用 **lookahead‑analysis** 检查是否误用了未来数据。
  ```bash
  freqtrade lookahead-analysis --strategy MyStrategy
  ```
- 使用 **recursive‑analysis** 检查指标的稳定启动期。
  ```bash
  freqtrade recursive-analysis --strategy MyStrategy
  ```

### 9.2 回测（Backtesting）
```bash
freqtrade backtesting \
    --strategy MyStrategy \
    --timeframe 5m \
    --timerange 20210101-20210131 \
    --export trades
```
- `--export trades` 会生成 `trades.json`，便于后续分析。
- 回测默认使用 **收盘价** 触发信号，可通过 `--export trade-analysis` 查看详细 ROI、DD 等指标。

### 9.3 前向测试（Dry‑run）
```bash
freqtrade trade \
    --strategy MyStrategy \
    --dry-run
```
- 在 `dry-run` 模式下，策略会在真实行情中产生信号，但不会实际下单，所有交易记录仅保存在日志中。
- 建议在完成回测后立即进行 **dry‑run**，确认两者结果相近后再考虑 `live`。

### 9.4 真实交易（Live）
确保已完成以下检查后再启动 `live`：
1. `startup_candle_count` 已正确设置。
2. 所有 **lookahead** 与 **recursive** 警告已解决。
3. `max_open_trades`、`stake_amount` 等配置已符合风险管理要求。
4. 通过 `freqtrade trade --strategy MyStrategy` 启动，观察日志输出 `INFO: Trade opened` / `INFO: Trade closed`。

## 10. 常见问题及最佳实践

| 问题 | 解决思路 |
|---|---|
| **回测结果与实盘差距大** | 检查是否使用了 **limit** 订单、是否有 `order_delay`、是否使用了 `adjust_trade_position` 等导致延迟的回调。 |
| **出现 FutureWarning：DataFrame `iloc` 警告** | 确保所有操作均为向量化（`.loc`），避免在 `populate_*` 中使用 `dataframe.iloc[-1]`。 |
| **指标 NaN 导致信号缺失** | 设置合理的 `startup_candle_count`，或在 `populate_indicators` 中使用 `fillna(method='ffill')` 进行填充（仅对非关键列）。 |
| **策略文件未被加载** | 确认文件所在目录已在 `config.json` 的 `strategy_path` 中声明，或使用 `--strategy-path` 参数指定。 |
| **冲突信号导致不下单** | 在 `populate_entry_trend`/`populate_exit_trend` 中加入互斥条件，或实现 `confirm_trade_entry`/`confirm_trade_exit` 手动过滤。 |

### 推荐工作流
1. **模板生成** → `freqtrade new-strategy --template minimal`。
2. **指标实现** → 在 `populate_indicators` 中加入必要指标。
3. **信号编写** → 使用 `dataframe.loc` 编写 `enter_` / `exit_` 条件。
4. **本地检查** → `lookahead-analysis`、`recursive-analysis`。
5. **回测** → `freqtrade backtesting`，审阅 `trades.json` 与 ROI 报表。
6. **Dry‑run** → 确认信号在实时行情中仍然有效。
7. **Live** → 小额资金启动，持续监控日志与交易记录。
