# 本地开发调试指南（CLI + 虚拟环境）

本文档面向希望在本机（Linux/macOS/Windows WSL）上进行 **Freqtrade** 开发与调试的用户，提供从虚拟环境搭建、虚拟 K 线数据生成，到实际调试的完整步骤。

---

#严重警告！严禁使用 "现货模式+期货数据" 方式进行回测和hyperopt操作！！！

## 1️⃣ 环境准备

### 1.1 系统依赖
| 软件 | 版本建议 | 安装方式 |
|------|----------|----------|
| Python | 3.11 (项目 `pyproject.toml` 指定) | `sudo apt install python3 python3-venv python3-pip` |
| Git | 任意 | `sudo apt install git` |
| gcc / make | 编译部分依赖 | `sudo apt install build-essential` |
| libssl-dev、libffi-dev、libsqlite3-dev | - | `sudo apt install libssl-dev libffi-dev libsqlite3-dev` |

> 若使用 **Docker** 本节可跳过，直接进入 2.2。

### 1.2 创建并激活 Python 虚拟环境
```bash
# 进入项目根目录
cd /home/kali/Project/freqtrade

# 创建 .venv 目录（一次性）
python3 -m venv .venv

# 激活（每次打开终端都需）
source .venv/bin/activate
```
> 激活后，提示符会出现 `(.venv)` 前缀，表示已进入隔离环境。

### 1.3 安装项目依赖
```bash
# 确保在虚拟环境中
pip install --upgrade pip
pip install -r requirements.txt
```
> `requirements.txt` 包含了运行和测试所需的全部 Python 包。如果你想要 `freqai`（机器学习）功能，可额外执行 `pip install -r requirements-freqai.txt`。

## 2️⃣ 建立虚拟的 K 线（OHLCV）数据

Freqtrade 支持两种方式生成/获取 K 线数据：
1. **下载真实交易所数据**（`freqtrade download-data`），适合回测真实策略。 
2. **生成合成/模拟数据**（`freqtrade backtesting --timerange` 与 `data_commands`），用于快速调试或单元测试。

本指南演示 **合成数据** 的简单生成流程，避免网络请求。

### 2.1 创建用户数据目录（可选）
```bash
freqtrade create-userdir --userdir user_data
```
> 将在 `user_data/` 下创建 `data/`、`strategies/` 等子目录。

### 2.2 生成模拟 K 线数据
> 使用 `freqtrade backtesting` 时如果目标目录不存在，系统会自动在 `user_data/data/<exchange>/<pair>/` 中写入 **示例数据**。我们可以手动触发一次生成：
```bash
# 以 Binance 为例，生成 BTC/USDT 1h 数据 2022-01-01~2022-01-07
freqtrade download-data -c config_examples/config_binance.example.json \
    --exchange binance --quote USDT --base BTC \
    --timerange 20220101-20220107 --timeframe 1h
```
> 若没有网络或不想请求 Binance，可直接使用 `freqtrade backtesting` 生成空白结构后自行填充。

### 2.3 使用 `data_commands` 生成随机数据（仅用于调试）
```bash
# 生成 100 条随机 K 线（列: time, open, high, low, close, volume）
python - <<'PY'
import random, csv, datetime, os

pairs = [('binance', 'BTC/USDT')]
start = datetime.datetime(2022,1,1)
rows = []
price = 30000.0
for i in range(100):
    ts = start + datetime.timedelta(hours=i)
    open_ = price
    high = open_ * (1 + random.uniform(0,0.01))
    low  = open_ * (1 - random.uniform(0,0.01))
    close = random.uniform(low, high)
    volume = random.uniform(10, 100)
    rows.append([int(ts.timestamp()*1000), open_, high, low, close, volume])
    price = close

# 保存路径遵循项目约定
path = 'user_data/data/binance/BTC_USDT/1h'
os.makedirs(path, exist_ok=True)
with open(f'{path}/data_1h.csv', 'w', newline='') as f:
    writer = csv.writer(f)
    writer.writerow(['timestamp','open','high','low','close','volume'])
    writer.writerows(rows)
print('随机 K 线已写入', f'{path}/data_1h.csv')
PY
```
> 生成的 CSV 文件即可被 `freqtrade backtesting` 读取。

## 3️⃣ 本地调试步骤

### 3.1 选定调试目标
| 目标 | 推荐命令 | 说明 |
|------|----------|------|
| **启动机器人**（实时/干运行） | `freqtrade trade -c config_examples/config_binance.example.json --dry-run --loglevel DEBUG` | `--dry-run` 防止真实下单，`--loglevel DEBUG` 输出详细日志。 |
| **回测策略** | `freqtrade backtesting -c config_examples/config_binance.example.json --strategy SampleStrategy --timerange 20220101-20220107 --loglevel DEBUG` | 使用前文生成的示例数据进行回测。 |
| **单元测试** | `pytest -q tests/` | 项目自带 pytest，用于代码层面的断言。 |

### 3.2 使用 Python 调试器（pdb）
1. 在策略文件（如 `user_data/strategies/sample_strategy.py`）中加入 `import pdb; pdb.set_trace()`。
2. 运行对应命令（如 `freqtrade backtesting …`），当执行到断点时会进入交互式调试。
3. 常用 pdb 命令：`n`（下一行），`c`（继续），`p variable`（打印），`l`（查看上下文）。

### 3.3 查看日志与输出
- **控制台**：所有 `--loglevel DEBUG` 信息直接打印。
- **日志文件**：默认保存在 `user_data/backtest_results/` 或 `user_data/logs/`（可在 `config.json` 中配置 `logging.file`）。
- **可视化**：使用 `freqtrade plot-profit`、`freqtrade plot-dataframe` 生成 HTML 报告，再用浏览器打开。

### 3.4 常见调试技巧
| 场景 | 操作 |
|------|------|
| 参数错误（Missing key） | 检查 `config.json` 中的 `api_key`、`api_secret` 是否缺失，或使用 `--dry-run` 避免要求。 |
| K 线为空或不匹配 | 确认 `user_data/data/<exchange>/<pair>/<tf>/` 路径与 `--exchange`、`--pair`、`--timeframe` 参数一致。 |
| 策略报错 | 在 `strategy` 类的 `populate_indicators`、`populate_entry_trend` 中加入 `print()` 或 `logger.info()` 打印中间变量。 |
| 代码改动未生效 | 确认已在虚拟环境激活状态下运行 `freqtrade`，并且 `user_data/strategies/` 中的文件被正确加载（`--strategy-path` 可强制指定路径）。 |

## 5️⃣ 常见问题 FAQ
1. **`ModuleNotFoundError: No module named 'freqtrade'`**
   - 确认已在 `.venv` 环境中执行 `pip install -r requirements.txt`，并且 `source .venv/bin/activate` 已生效。
2. **`AttributeError: 'NoneType' object has no attribute 'something'`**
   - 多数是因为数据文件路径不匹配或 `config.json` 中的 `pairlist` 为空。检查 `pairlist` 是否包含所使用的交易对。
3. **日志文件没有生成**
   - 在 `config.json` 中启用文件日志：`"logging": { "loglevel": "debug", "logfile": "user_data/logs/freqtrade.log" }`
4. **Docker 与本地虚拟环境冲突**
   - 两者是独立的运行方式，建议在同一时间只使用一种方式调试，避免共享同一 `user_data` 目录导致权限问题。
