# Freqtrade 数据库结构说明

Freqtrade 使用 SQLite（也支持 MySQL / PostgreSQL）持久化运行时产生的核心数据。以下文档概括了项目自带的主要表结构、关键字段含义以及使用场景，帮助开发者在自定义持久化或迁移数据时快速定位。所有表均位于 **user_data/**（默认 `user_data/freqtrade.db`），通过 SQLAlchemy ORM 定义，代码位于 `freqtrade/persistence/` 包。

---

## 1. 主表概览

| 表名 | 对应模型 | 作用 | 关键字段 |
|------|----------|------|----------|
| **trades** | `Trade` | 持久化每一笔完整交易（从开仓到平仓） | `id`, `pair`, `exchange`, `strategy`, `open_date`, `close_date`, `is_open`, `amount`, `open_rate`, `close_rate`, `realized_profit`, `fee_open`, `fee_close`, `order_type`, `leverage`, `margin_type`, `funding_fees` |
| **orders** | `Order` | 记录交易过程中每一次订单的提交、成交、撤销等状态 | `id`, `trade_id` (FK), `type` (limit/market), `side` (buy/sell), `price`, `average`, `amount`, `filled`, `remaining`, `status`, `order_id`, `order_timestamp`, `cost`, `fee`, `fee_currency`, `exchange`, `is_open` |
| **order_fills** (内部) | `OrderFill`（在 `Order` 中通过 relationship `fills`） | 每笔订单的逐笔成交明细（主要用于币安等交易所的部分成交） | `id`, `order_id` (FK), `price`, `amount`, `fee`, `timestamp` |
| **pairlock** | `PairLock` | 用于 “pair lock” 功能，防止同一交易对在同一时间内被多策略竞争 | `pair`, `exchange`, `strategy`, `lock_timestamp`, `unlock_timestamp` |
| **key_value_store** | `KeyValueStore` | 轻量级键值存储，保存如 `last_process_timestamp`、`api_key`（加密）等全局配置信息 | `key`, `value`, `expire_at` |
| **custom_data** | `CustomDataWrapper` / `_CustomData` | 允许插件向数据库写入自定义结构（如策略指标、监控数据） | `id`, `trade_id` (FK), `key`, `value` |

## 2. `Trade` 表字段详解

| 字段 | 类型 | 含义 | 备注 |
|------|------|------|------|
| `id` | INTEGER PK | 自动递增主键 |
| `pair` | TEXT | 交易对，如 `BTC/USDT` |
| `exchange` | TEXT | 交易所名称 |
| `strategy` | TEXT | 使用的策略类名 |
| `open_date` / `close_date` | DATETIME | 开仓、平仓时间（UTC） |
| `is_open` | BOOLEAN | 是否仍在持仓中 |
| `amount` | FLOAT | 开仓时的基准资产数量 |
| `open_rate` / `close_rate` | FLOAT | 开仓、平仓的成交价（USD） |
| `realized_profit` | FLOAT | 已实现盈亏（基准货币） |
| `fee_open` / `fee_close` | FLOAT | 开平仓手续费（基准货币） |
| `fee_open_currency` / `fee_close_currency` | TEXT | 手续费计价货币 |
| `order_type` | TEXT | `market`、`limit`、`stop_limit` 等 |
| `leverage` | FLOAT | 杠杆倍数（若为 `None` 表示现货） |
| `margin_type` | TEXT | `isolated` 或 `cross`（仅期货） |
| `interest_rate` | FLOAT | 融资利率（仅保证金/期货） |
| `funding_fees` | FLOAT | 期货持仓期间累计资金费 |
| `record_version` | INTEGER | 数据结构版本号（用于向后兼容迁移） |
| `enter_tag` / `exit_tag` | TEXT (max 30) | 自定义标签，常用于标记特殊进场/离场原因 |
| `stop_loss_pct` / `take_profit_pct` | FLOAT | 止损、止盈阈值（相对比例） |
| `trading_mode` | TEXT | `spot`、`margin`、`futures` |

> 以上字段均通过 SQLAlchemy `mapped_column` 映射，字段可在代码 `freqtrade/persistence/trade_model.py` 中查看完整定义。

## 3. `Order` 表字段详解

| 字段 | 类型 | 含义 |
|------|------|------|
| `id` | INTEGER PK |
| `trade_id` | INTEGER FK → `trades.id` |
| `type` | TEXT | 订单类型（`limit`、`market`、`stop_limit` 等） |
| `side` | TEXT | `buy` 或 `sell` |
| `price` | FLOAT | 用户提交的目标价格（limit） |
| `average` | FLOAT | 实际成交均价（若部分成交） |
| `amount` | FLOAT | 订单的原始数量 |
| `filled` | FLOAT | 已成交数量 |
| `remaining` | FLOAT | 剩余未成交数量 |
| `status` | TEXT | `open`、`closed`、`canceled`、`expired` |
| `order_id` | TEXT | 交易所返回的唯一订单 ID |
| `order_timestamp` | DATETIME | 订单创建时间 |
| `cost` | FLOAT | 成本 = filled * average + 费用 |
| `fee` | FLOAT | 交易所收取的手续费 |
| `fee_currency` | TEXT | 手续费计价币种 |
| `exchange` | TEXT | 所属交易所 |
| `is_open` | BOOLEAN | 与 `status` 同步的布尔标志 |

---

## 4. 关联表 `order_fills`

当交易所返回 **部分成交** 信息时，Freqtrade 会把每一次成交记录在 `order_fills` 中，供回测与分析使用。字段主要包括 `price`, `amount`, `fee`, `timestamp`，并通过 `order_id` 关联到 `orders`。

---

## 5. 其它辅助表

1. **pairlock**：记录当前被锁定的交易对，以防止多策略竞争同一对。字段 `pair`, `exchange`, `strategy`, `lock_timestamp`, `unlock_timestamp`。
2. **key_value_store**：键值对存储，用于持久化如 `last_process_timestamp`、`strategy_state`、缓存等轻量数据。
3. **custom_data**：插件/策略自定义的数据，用 `key`、`value`（JSON）存储，可通过 `CustomDataWrapper` 访问。

---

## 6. 常见查询示例（SQLite）

```sql
-- 查询最近 10 笔已平仓交易及盈亏
SELECT id, pair, open_rate, close_rate, realized_profit
FROM trades
WHERE is_open = 0
ORDER BY close_date DESC
LIMIT 10;

-- 获取某笔交易的所有订单及成交明细
SELECT o.id, o.type, o.side, o.price, o.filled, f.price AS fill_price, f.amount AS fill_amount
FROM orders o
LEFT JOIN order_fills f ON f.order_id = o.id
WHERE o.trade_id = 123;
```

## 7. 迁移 / 扩展建议

- **添加自定义字段**：在 `custom_data` 表中使用 `key`=`my_metric`、`value`=JSON 保存，不需要改动核心模型。
- **切换数据库**：修改 `freqtrade/configuration/configuration.py` 中 `db_url` 为 `postgresql://...` 或 `mysql://...`，SQLAlchemy 会自动映射同样的模型。
- **版本升级**：每次模型改变会递增 `record_version`，迁移脚本位于 `freqtrade/persistence/migrations.py`，请在升级前运行 `freqtrade db upgrade`（或手动执行脚本）以保持兼容。
